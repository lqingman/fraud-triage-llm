# Phase 5b — Multi-signal model promotion policy

## Why F1 alone is unsafe

A candidate can improve fraud F1 while emitting malformed JSON, exceeding a
latency SLO, failing under load, or regressing a responsible-AI test. Promotion
therefore requires evidence from three independent layers:

- offline model quality: F1, PR-AUC, and JSON validity;
- operational reliability: p95 latency and error rate;
- Responsible AI: an executable suite-level pass covering schema validity,
  prompt-injection recall, demographic counterfactual consistency, benign
  false-positive rate, and unsupported evidence spans.

## Fail-closed decision

`src/eval/responsible_ai.py` first evaluates structured predictions on a
versioned challenge set and writes its metrics and failed checks. Then
`src/eval/promotion.py` loads thresholds from `config/config.yaml`, evaluates
every signal, and writes an auditable JSON decision containing the observed
value, operator, threshold, and result for each check. A missing file, missing
metric, or failed Responsible AI suite cannot be treated as a pass.

The command exits non-zero on rejection, so it is usable as a CI/CD approval
gate:

```bash
python -m src.eval.responsible_ai \
  --cases reports/candidate_responsible_ai_cases.jsonl \
  --out reports/responsible_ai.json

python -m src.eval.promotion \
  --metrics reports/metrics.json \
  --operational-metrics reports/operational_metrics.json \
  --responsible-ai reports/responsible_ai.json \
  --out reports/promotion_decision.json
```

GitHub Actions runs the Responsible AI evaluator and promotion policy after the
existing evaluation regression gate using committed, license-safe fixtures.
The fixtures prove the evaluators execute on every push; their committed
predictions do not substitute for predictions freshly generated by a real
candidate model, a real load test, or a production deployment.

This phase decides eligibility but does not deploy a model or register the
QLoRA adapter. Production rollout, canary analysis, alias movement, and rollback
remain separate authorized deployment actions.
